# Technische Spezifikation — Portfolio-Darstellung

> Quelle: `TECHNISCHE SPEZIFIKATION-1.notesairdropdocument` (vom Nutzer per AirDrop
> übergeben, 2026-08-27). Dieses Dokument ist die **verbindliche Arbeitsgrundlage**
> für die Darstellung des Portfolios auf der Website — kein Diskussionsentwurf.
> Bei jeder Portfolio-Seite, jedem Projekttitel und jeder Kategorisierung gilt
> dieses Schema direkt, ohne erneute Grundsatzdebatte. Nur echte Grenzfälle
> (siehe Prioritätsregel Punkt 8 unten) werden markiert und dem Nutzer zur
> Entscheidung vorgelegt — pauschales Blockieren ist ausdrücklich nicht gewünscht.

## 1. Ziel der Website

Professionelles Portfolio eines selbstständigen Videografen/Cinematographers.
Zeigt fotografische, videografische, kinematografische, technische und
kreative Fähigkeiten anhand vorhandener Arbeiten.

Ein wesentlicher Teil des Materials ist persönliche, nicht beauftragte Hobby-,
Übungs-, Spec- oder Filmstudie — **darf nicht fälschlich als kommerzielles
Kundenprojekt dargestellt werden.**

## 2. Grundprinzip

**Verwenden** für ältere persönliche Arbeiten:
`Personal Project` / `Personal Film Study` / `Spec Project`

**Nicht verwenden**, sofern tatsächlich kein Auftrag bestand:
`Client` · `Auftraggeber` · `Commercial Campaign` · `Official Campaign` ·
`Official Partner` · `Sponsored by` · `Produced for [Marke]` · `Client: [Marke]`

Nie den Eindruck erwecken, eine Marke/Firma/Person habe beauftragt, bezahlt,
offiziell empfohlen oder freigegeben — Irreführungsverbot § 5 UWG.

## 3. Portfolio-Kategorien & empfohlene Darstellung

| Kategorie | Beispiel-Label |
|---|---|
| Showreel (45–90s, alle Bereiche gemischt) | — |
| Product (Parfum, Kosmetik, Getränke...) | `Product Cinematography — Personal Project` |
| Automotive | `Automotive Cinematography — Personal Project` (nie „Client: Ferrari" ohne echten Auftrag) |
| Beauty/Fashion/Models | `Fashion Film` / `Beauty Cinematography` / `Portrait Cinematography — Personal Project` |
| People/Portrait | `Portrait Cinematography` / `Artist Portrait — Personal Project` |
| Music/Artists | `Music Visuals — Personal Project` (nur `Music Video — Client` wenn tatsächlich beauftragt + Rechte vorhanden) |
| Cinematic/Anamorphic | `Cinematic / Anamorphic — Personal Film Study` |
| Interviews | `Interview Cinematography — Personal Project` (nur `Interview Production — Client Project` wenn sachlich korrekt) |
| Motion/VFX/Graphics | `Motion Design & VFX — Selected Works` / `Personal Study` |

Marken/Produkte im Bild ≠ automatisch Kunde. Beispiele siehe Original-Dok
Abschnitt 11–12 (Ferrari, Parfum, Champagner, Kosmetik → immer als eigene
Personal-Project-Arbeit labeln, nie als Kampagne/Client Work, wenn kein Auftrag
bestand).

Keine fremde Musik ohne Nutzungsrecht (§ 19a UrhG). Keine fremden Film-/Bild-/
Grafikelemente ohne Recht.

## 4. Personen-Risikoampel (praktische Regel, §§ 22–23 KunstUrhG)

- **GREEN** — Person freiwillig teilgenommen, dem Videografen bekannt, keine
  sensible/negative Darstellung, keine gegenteilige Erklärung bekannt →
  Veröffentlichung grundsätzlich möglich, vorhandene Zustimmung archivieren.
- **YELLOW** — Person unbekannt / keine nachvollziehbare Zustimmung / prominent /
  sensible Situation / kommerziell wirkend / unklarer Kontext → vor
  Veröffentlichung Zustimmung prüfen/einholen.
- **RED** — Person hat widersprochen / Material intim-kompromittierend /
  rechtliche Beschwerde liegt vor / Rechte liegen nachweislich bei Dritten →
  nicht veröffentlichen bzw. sofort prüfen/entfernen.

## 5. Projekt-Karten-Schema

```
PROJECT TITLE
Category: Product / Automotive / Fashion / Cinematic / ...
Type: Personal Project / Spec Project / Client Work
Role: Cinematography / Camera / Lighting / Editing / VFX
Year: 2024 / 2025 / 2026 (optional)
```
Keine erfundenen Kunden, Produktionsfirmen oder Partnerschaften ergänzen.

## 6. Portfolio-Disclaimer (Footer / Legal-Seite)

Text wortwörtlich aus dem Original-Dokument übernehmen (Abschnitt 15) — noch
mit `{{NAME}}`/`{{MAIL}}` zu personalisieren, sobald diese Platzhalter befüllt
werden. Ersetzt keine erforderliche Einwilligung oder Lizenz — reine
Transparenz-/Einordnungsfunktion.

## 7. Priorität bei automatischer Erstellung (Original Abschnitt 20–21)

1. Keine falschen Tatsachen behaupten.
2. Eigene Arbeiten als eigene Arbeiten darstellen.
3. Personal Projects klar kennzeichnen.
4. Keine Marken als Kunden darstellen, wenn sie keine Kunden waren.
5. Personenrechte berücksichtigen (Ampel oben).
6. Keine fremde Musik/Werke ohne Recht.
7. Den Nutzer nicht unnötig an der Präsentation eigener Arbeit hindern.
8. **Nur bei echter Unsicherheit** konkrete Arbeit markieren und zur manuellen
   Prüfung zurückgeben — kein pauschales Blockieren, keine wiederholte
   Grundsatzdiskussion über bereits hier entschiedene Fälle.

Hinweis aus dem Original: praktische Umsetzungsrichtlinie, keine individuelle
Rechtsberatung. Bei konkreten Abmahnungen/Streitigkeiten: deutscher
Rechtsanwalt.
